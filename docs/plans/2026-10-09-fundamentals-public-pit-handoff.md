# 재무 공시 공개 시점 기준 PIT 보완 작업

요청일: 2026-10-09 KST.
작업 대상: 메인 채팅 **백테스트용 clean dataset 설계**.
상태: 사용자 요청을 정리한 작업 지시서. 채팅 전달 도구 오류로 메인 채팅 접수와 구현 착수는 확인되지 않았다.

## 사용자 요구

한국·미국 재무 데이터를 다시 점검하고, 공개정보 기준 과거 백테스트에서 **검증된 공시 공개 시점 이후부터 당시 원본 값을 사용**하도록 구현한다. 정정값은 정정 공개 이후에만 사용할 수 있어야 한다. 현재 수집한 데이터도 필요한 범위에서 보완한다.

수집 시각을 공시 시각으로 바꾸는 작업이 아니다. 원래 수집·추출·최초 발견 시각을 보존하면서 공시 원본·정정 버전과 공개 시점의 검증된 연결을 추가한다. 작업과 결과 보고는 메인 채팅에서 진행한다.

## 현재 확인한 구현 경계

- `src/backtest_data/fundamentals/collection.py`의 SEC·OpenDART XBRL 수집은 `available_at=response.captured_at`을 전달한다. 실제 수집 호출에서 `published_at`을 전달하지 않고 capture-only로 처리한다.
- `src/backtest_data/fundamentals/dart_json_collection.py`의 JSON 계정 수집도 같은 수집 시각 기준을 사용한다.
- SEC `filingDate` 및 공급자가 제공하는 `acceptanceDateTime`, OpenDART `rcept_dt` 등의 공시 목록 필드는 `CollectionJob.request.filing`에 보관하는 경로가 있다. 원계정의 검증된 과거 공개 가용 시각으로 연결하는 작업은 남아 있다.
- 재무 기간의 `period_start`, `period_end`, `instant`와 공시 공개 시점은 서로 다른 개념이다. 기간 종료일을 공개일로 사용하지 않는다.

위 사항은 옆 채팅에서 코드로 확인한 내용이다. 구현 전에 메인 채팅의 최신 코드와 실제 SQL 상태를 다시 확인한다.

## 두 가지 시간 기준

| 조회 방식 | 사용할 시점 |
|---|---|
| `reconstructed_public` | 검증된 공개 시점 이후에 당시 공개된 정확한 원본 또는 정정 버전을 사용 |
| `observed_system` | 실제 시스템의 수집·추출·최초 발견·채택 시각 이후에만 사용 |

2023년 결산 공시가 2024년 3월 공개되고 2026년에 수집된 경우, 원본과 공개 시점을 검증한 `reconstructed_public` 조회는 2024년 공개 이후 원본을 사용할 수 있어야 한다. 같은 자료의 `observed_system` 조회는 실제 2026년 관측 이전에 사용할 수 없다.

현재 값 또는 최신 정정값을 과거 공시 날짜에 연결하지 않는다. 같은 회계 기간이라도 공시 버전별 숫자와 가용 시점이 구분돼야 한다.

## 공개 시점 증거와 데이터 보완

1. 기존 재무 원계정·공시·문서·작업 메타데이터를 감사해 공개 날짜·시각, accession 또는 접수번호, 정확한 원본 숫자 버전의 연결 가능 범위를 집계한다.
2. SEC 접수 시각과 실제 공개 가용 시점의 관계, 시간대와 근거를 명시한다. 접수 시각을 무조건 최초 공개 시각과 같다고 가정하지 않는다.
3. OpenDART 등에서 날짜만 제공하면 날짜 정밀도와 보수적인 일봉 사용 시점 정책을 명시한다. 시각이 불명확한 자료를 공시일 장 시작부터 알고 있었다고 처리하지 않는다. 장중·장후 공개와 거래소 세션을 구분한다.
4. 최초 공시·정정·철회와 해당 버전의 숫자를 연결한다. 정기보고서와 그보다 이른 실적 발표·보도자료의 범위도 구분한다.
5. 원본 버전 근거가 부족한 자료는 capture-only 또는 격리를 유지하고, 필요한 경우 원래 accession·접수번호별로 다시 수집한다. OpenDART JSON의 최신 응답 접수번호 불일치 방어는 유지한다.
6. 기존 데이터 보완은 재실행 가능한 배치로 진행한다. 확인·보완·미확인 건수와 이유를 SQL 근거로 보고한다.

기존 immutable 원계정·공시·문서·선택 결정과 과거 봉인 릴리스는 보존한다. 필요하면 append-only 공개시점 증거와 새 qualification·검증 규칙으로 보완한다. `captured_at`, `extracted_at`, `first_seen_at`을 덮어쓰거나 기존 날짜를 일괄 소급하지 않는다.

새 공개시점 정책을 고정한 규칙·릴리스 버전을 명시한다. 기존 v5 릴리스를 새 규칙으로 암묵적으로 재해석하지 않는다. 공개시점 근거만으로 회계 기간·연결/별도·단위·주식 기준·지표 계산 적격성의 기존 결함을 해소했다고 표시하지 않는다.

## 최소 회귀 검증

- 공개 전 cutoff에서 unavailable, 최초 공개 후에는 원본만 보이고, 정정 공개 후에만 정정값이 보인다.
- 같은 공시를 뒤늦게 수집해도 `observed_system`의 과거 결과가 바뀌지 않는다.
- 회계 기간 종료일을 공시 공개일로 사용하지 않는다.
- 최신 정정값, 미래 공시, 다른 회사 또는 다른 접수번호의 값이 과거 조회로 유입되지 않는다.
- 날짜만 있는 공개 정보에 정밀도와 보수적인 거래 가능 시점 정책이 적용된다.
- 원본 숫자·회사·accession 또는 접수번호·단위·context·문서 버전의 매칭을 검증한다.
- 같은 보완 배치를 다시 실행해도 중복이 생기지 않고, 과거 봉인 릴리스의 기존 조회 결과가 재현된다.
- 실제 SQL 보완 건수, 공개시점 적격 범위, 여전히 capture-only 또는 unavailable인 범위를 보고한다.

## 수집 운영과 작업 범위

현재 한국·미국 전종목과 ETF·ETN 대상, 수집 체크포인트, 이미 실행 중인 수집기와 2시간 감시는 보존한다. 중복 수집이나 데이터 유실을 피하고, 필요한 수집기 교체는 정확한 프로세스 신원과 재개 지점을 확인한 뒤 제어된 방식으로 진행한다.

진행과 검증 결과는 메인 채팅에서 보고한다. 이 요청은 재무 PIT 구현과 기존 데이터 보완을 포함한다. [무료 원격 갱신과 로컬 SQL 운영 설계](../data/free-remote-update-local-sql.md)의 실제 배포는 이번 작업 범위에 포함하지 않는다.
