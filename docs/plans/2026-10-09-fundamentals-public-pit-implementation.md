# Financial public PIT implementation

**Goal:** Execute the user-approved handoff in `2026-10-09-fundamentals-public-pit-handoff.md`: verified original versions become visible only after public disclosure; amendments only after their own disclosure; preserve physical clocks and every v5 sealed response.

**Architecture:** Append immutable document-bound publication evidence. A shared resolver supplies effective public clocks to the explicitly versioned v6 reader and metric materializer. Collection/version verification owns regulator evidence; availability qualification never overrides source extraction adoption. Existing hashed model columns and stored clocks remain unchanged.

**Stack:** PostgreSQL, SQLAlchemy, Alembic, existing bounded regulator HTTP clients and extraction inventory gates.

## Evidence and conservative policy

- Bind document ID/hash, filing ID, issuer, provider accession/receipt, exact original numeric inventory/context/unit/scope, authoritative public-distribution record, policy version, evidence capture and recording times.
- SEC acceptance time/filingDate alone and HTTP Last-Modified are insufficient. Prefer dated official Feed/Oldloads membership plus the exact disseminated numeric instance. A dated dissemination archive supports a public DAY; use the following America/New_York calendar-day boundary, explicitly recorded as conservative date precision, not a claimed first website timestamp. Header and issuer identities must agree; generated XML must match an original disseminated version's full numeric semantics or remain unqualified.
- DART uses verified public receipt day plus receipt-specific original and exact numeric binding. Use following Asia/Seoul day boundary. Latest JSON response matching a receipt is not by itself a historical-original guarantee; mismatched/newer receipts remain excluded. Date bounds are information availability, not an invented exchange opening session. Missing verified session calendars remain gaps.
- Original, amendment, replacement, rejection and dated withdrawal remain separate. Same-day unresolved version order must fail closed. Unavailable retrieval attempts must not revoke a previously verified original; explicit rejection/withdrawal events have their own immutable history.
- `observed_system` retains actual capture/extraction/first-seen/materialization/decision cutoffs. Public qualification does not clear fiscal, unit, scope, share-basis or calculation gaps.

## Ordered implementation and verification

### Shared implementation contract

The new model is `FinancialPublicationEvidence` in `fundamentals/publication_models.py`; no legacy columns change. Fields bind document, filing, issuer, source/accession and original document hash, status (`qualified`, `unavailable`, `rejected`, `withdrawal`), nullable public day/effective bound, precision/timezone, evidence capture/recording times, policy version, deterministic assertion hash and evidence JSON. Optional supersession references identify the exact earlier assertion. Failed retrieval is an attempt, not a revocation. An explicit rejection revokes its targeted assertion in a new release; withdrawal affects the original only after its own public bound. Evidence selection uses only the supplied frozen membership, never live evidence outside the release.

`resolve_document_availability(document, filing, evidence_rows, *, history_mode, as_of)` returns `{effective_available_at, status, reason, evidence_ids, precision, policy_version, withdrawn}`. Without verified evidence, public mode returns the existing conservative capture bound with a capture-only gap. Observed mode keeps the existing stored/physical clocks and only sees recorded events after their real recording/capture times. Rejection does not backdate physical observation. Construct next-date local midnight with `ZoneInfo`; do not add 24 UTC hours across DST. Trading-session eligibility is separately unavailable without a verified calendar.

Original version matching compares complete inventories and deterministic normalized facts: expanded concept identity, context entity/scheme, dimensions, duration/instant dates, expanded units, scope, nil/value, scale/decimals/precision and parse status. Record source and original body/member hashes, node counts, and complete matching digest. Equivalent opaque context labels require a full structural mapping; a few matched metrics, same receipt, generated filename or acceptance date are insufficient. Missing/unsupported/ambiguous numeric nodes fail qualification. SEC proof must show this instance's actual membership in the dated disseminated Feed/Oldloads bundle. DART proof needs authoritative public receipt-list membership AND the requested receipt-specific original, not a viewer that silently selects the latest correction.

v6 materialization replaces stored-availability prefiltering with verified effective input eligibility; new signatures pin public policy and exact evidence refs. Store actual capture/completion clocks unchanged, project public bounds for calculation, and make future-input validation policy-aware. v5 signatures, rows, decisions, clock rules and full response payloads remain unchanged.

v6 research scope declares exact whole-document IDs, audit watermark, original full target and verified/missing/total denominators. Excluded documents return unavailable/scope-excluded, never zero-filled values; price queries on a financial-only seal fail scope checks. Derived dependencies bring their complete source documents/inventories into closure. The one-million limit includes all aliases/catalog/raw/decisions/issues/evidence. Multiple document-scoped releases are separate research seals, not one claimed full-scale streaming release. Capture explicit v5 source/canonical/metric responses and hashes in both modes before migration, and compare after evidence append and v6 sealing.
