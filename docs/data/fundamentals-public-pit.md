# Financial public PIT

`release_query_v6` reconstructs financial information from complete, verified original versions. `release_query_v5` remains the default compatibility policy for legacy releases. Existing SQL clocks and sealed rows are unchanged. New publication assertions are append-only rows in `financial_publication_evidence` (migration `b830df281926`).

A historical timestamp is available only when the original matches the complete stored numeric inventory, units, entity, periods, dimensions and exact document version. SEC proof uses dated official dissemination archives; acceptance and filing dates alone are insufficient. DART needs public receipt-list membership and the receipt-specific original, rather than a latest-only JSON response. Source bodies are held in bounded memory; their hashes and useful structured values/provenance are stored in SQL.

For day-level publication evidence the conservative eligibility bound is the following local calendar-day midnight: America/New_York for SEC and Asia/Seoul for DART, with DST-aware construction. Missing exchange session calendars remain an explicit gap. A correction becomes usable after its own verified bound. Same-day conflicting versions fail closed. `observed_system` additionally requires actual capture, extraction, first-seen, materialization and adoption times; eligibility and verified version order are separate. Rejections target one assertion; withdrawals take effect after their own bound. Retrieval failures do not revoke valid prior proof.

Latest-version selection checks ambiguity in the latest eligible certified-bound group; a conflict superseded by a later certified version cannot suppress that later version. If an eligible capture-only value conflicts with the certified winner, its public ordering is unknown and latest-value/metric selection fails closed. A late collection timestamp cannot overwrite a certified correction. Equal capture-only values retain the certified candidate. All-visible source queries may still return both versions with their explicit qualification metadata.

Full-target audit and resumable verification:

```powershell
python -m backtest_data publication audit --manifest-id FULL_TARGET_ID --audit-path artifacts/public-pit/audit.json
python -m backtest_data publication verify --audit-path artifacts/public-pit/audit.json --progress-path artifacts/public-pit/progress.json --budget-seconds 300
```

Audits pin exact original document IDs, hashes and a source watermark, with the original security target and denominators. Subsequent insertions cannot drift the audited target. Verification commits complete document outcomes and saves an idempotent contiguous cursor. Repeat the verify command to resume; `--retry-unavailable` starts another pass against the same audit while preserving prior pass history. `audit_pass_complete` means every audited document has an outcome, including unsupported/blocked outcomes; it does not mean clean coverage is complete.

Daily SEC archives can exceed the default compressed limit of 64 MiB. `--archive-compressed-mb` permits 1–512 MiB and `--archive-total-mb` permits 1–8,192 MiB of total expansion (default 512 MiB). These are resource bounds, not permission to truncate a certificate. The target submission retains its independent 32 MiB member limit. Unrelated large regular submissions are drained in bounded chunks after checking their real SGML accession headers; malformed, ambiguous, unsupported or unsafe archives remain unqualified. Within one run, repeated SEC archive size/access failures reuse the recorded failure rather than downloading the same oversized response for every document. Transient failures remain retryable. Original financial bodies are not saved to disk.

New metrics explicitly select `--query-version release_query_v6`; they pin the exact publication evidence and definition in their signatures, preserve physical clocks, and retain independent fiscal/scope/currency/share-basis qualifications. No missing value becomes zero. v5 metric selection excludes v6 rows.

Bounded v6 research seals use `release build --query-version release_query_v6 --financial-scope SCOPE.json`. The scope declares whole document IDs, the original audit watermark and total/verified/missing audit counts. Complete source inventories and dependencies are frozen, together with the later certification/materialization snapshot. The original full security target remains visible; actual included/excluded document counts and missing coverage are explicit. Price and valuation queries are excluded from this financial scope. The existing million-row guard remains in place; these scopes do not claim a full-scale streaming seal.

Actual source access, version mismatch and maintenance gaps remain in SQL. OpenDART's announced original/XBRL maintenance through 2026-10-11 18:00 KST must not be treated as completed original verification. Latest-only financial JSON remains capture-only until a complete receipt-specific original equivalence is established.
