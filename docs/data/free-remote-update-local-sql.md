# 무료 원격 데이터 갱신과 로컬 SQL 운영 설계

기준일: 2026-10-09 KST. 이 문서는 초기 설계안이다.

2026-10-11 사용자 승인으로 공개 GitHub Release 전달 방식과 KRX 계정의 실제 인계를 진행했다. 현재 운영 방식과 연결 범위는 [원격 파이프라인](remote-pipeline.md)을 따른다. 아래 비공개 임시 저장소 제안은 초기 대안이다.

한국·미국 전종목의 가격·거래량·재무 수치를 로컬 PostgreSQL에 보관하고, PC가 꺼진 동안에는 원격 수집기가 새 데이터와 정정분을 수집한다. PC를 켜면 변경분을 내려받아 기존 SQL에 추가한다. ETF·ETN을 포함한 전체 대상은 유지하며, 비용 때문에 대상 종목을 줄이지 않는다.

우선 검토할 구성은 **공개 GitHub 저장소의 표준 Actions 실행기 + 비공개 임시 저장소 + 로컬 PostgreSQL**이다. 무료 사용량 안에서 서비스 이용료 월 0원을 목표로 한다. 로컬 장비·디스크·전기 비용과 유료 데이터 공급자 비용은 이 목표에 포함하지 않는다.

현재 수집 기능과 구현 경계는 [구현 상태](implementation-status.md)를 따른다. 이 설계안은 GitHub 배포, 저장소 공개 전환, API 키 등록 또는 원격 동기화가 완료됐다는 뜻이 아니다.

## 데이터 저장과 전달 구조

```mermaid
flowchart LR
    A[공개 저장소의 수집 코드] --> B[GitHub Actions 수집과 검증]
    B --> C[비공개 임시 저장소의 변경분과 체크포인트]
    C --> D[PC에서 변경분 다운로드]
    D --> E[로컬 PostgreSQL 전체 이력]
    E --> F[적재와 백업 확인]
    F --> C
```

| 계층 | 보관하거나 처리할 내용 | 운영 책임 |
|---|---|---|
| 공개 코드 저장소 | 수집·검증·내보내기 코드와 의존성 | API 키, 데이터, 전략 코드의 공개 여부와 분리 |
| 원격 실행기 | 해당 실행의 수집·검증과 배치 생성 | 종료 전에 영속적인 배치와 체크포인트 저장 |
| 비공개 임시 저장소 | 압축 변경분, 배치 목록, 수집 진행 상태, 필요한 마스터 증거 | 로컬이 받지 못한 데이터와 재개 상태 보존 |
| 로컬 PostgreSQL | 가격·재무 수치, 출처, 정정·검증·매핑·계산 이력 | 전체 이력의 SQL 저장과 백테스트 조회 |
| 로컬 동기화 | 마지막으로 적재한 배치 이후의 데이터 | 중복 방지, 무결성 검증, 적재 완료 기록 |

임시 저장소의 파일은 SQL로 전달하기 위한 자료다. 전체 SQL 저장 방침을 바꾸거나, SEC·OpenDART 원문 문서 전체를 영구 저장하는 용도로 사용하지 않는다. 가격·종목 마스터 원응답 등 기존 저장 계약이 요구하는 증거는 SQL 참조와 함께 전달한다.

PC가 꺼져 있어도 원격 수집을 계속하려면 내려받기 전의 데이터와 체크포인트를 원격에 보관해야 한다. 전체 DB를 로컬에 두더라도 이 임시 보관 공간은 필요하다. 실행기 내부 디스크나 캐시만을 유일한 재개·복구 수단으로 사용하지 않는다.

## 무료 이용 조건

### GitHub Actions 실행

공개 저장소에서 **표준 GitHub 제공 실행기**를 사용하면 실행시간 이용료가 무료다. 큰 사양의 larger runner는 공개 저장소에서도 유료다. 비공개 저장소의 GitHub Free는 월 2,000분이 포함되며, 다른 저장소와 작업에서 사용한 실행량도 같은 계정 한도에 영향을 준다. [GitHub 공식 요금](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

GitHub 제공 실행기는 작업 하나당 최대 6시간이다. 긴 수집은 제한 전에 체크포인트를 저장하고 다음 실행에서 이어간다. 예약 실행은 지연될 수 있으므로 실제 실행 여부와 수집 구간을 기록하고, 빠진 구간은 다음 실행에서 다시 계획한다. [작업 제한](https://docs.github.com/en/actions/reference/limits), [예약 실행 조건](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

코드 공개와 데이터 공개는 별도로 정한다. API 키는 Secrets에 등록하고, 데이터는 비공개 저장소와 로컬 SQL에 보관한다. 키·토큰·DB 인증정보를 코드, Git 이력, 로그 또는 배치에 포함하지 않는다. [Secrets 설정](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)

### 원격 임시 저장소

Cloudflare R2 Standard를 우선 후보로 둔다. 월 무료 사용량은 저장 공간 **10 GB-month**, 쓰기 계열 작업 **100만 요청**, 읽기 계열 작업 **1,000만 요청**이며 직접 다운로드 전송료는 무료다. 무료 범위는 Standard에 적용되고, 한도 초과분은 유료다. [R2 공식 요금](https://developers.cloudflare.com/r2/pricing/)

10 GB-month는 매월 새로 10GB를 추가할 수 있다는 뜻이 아니다. 저장량의 월 사용량 기준이므로 전체 이력을 계속 쌓아 두면 무료 범위를 넘을 수 있다. 계정의 다른 R2 사용량까지 포함해 관리한다.

운영 시에는 무료 한도보다 낮은 내부 기준을 둔다. 예를 들어 저장량 8GB 근처에서 알리고, 계속 증가하면 새 업로드를 보류한다. 이 값은 초기 제안이며 실제 배치 크기와 보관 기간으로 조정한다. 제공 서비스의 과금 상한을 보장하는 기능과 구분한다.

로컬 적재와 백업이 확인된 배치만 원격 삭제 대상으로 삼는다. 미수신 배치를 무료 용량 확보 목적으로 지우지 않는다. PC가 오래 꺼져 있어 미수신 자료가 쌓이면 수집을 보류하고 알린다. 삭제된 임시 자료는 독립적인 전체 백업 사본으로 간주하지 않는다.

### 로컬 SQL 비용

기존 PC·디스크와 로컬 PostgreSQL을 사용하면 별도의 클라우드 DB 저장 이용료가 없다. 따라서 공개 표준 Actions의 무료 실행과 임시 저장소의 무료 한도를 함께 지키면 서비스 이용료 월 0원 구성이 가능하다. 실제 용량과 실행량을 측정하기 전에는 무료 운영을 확정하지 않는다.

## 수집 빈도와 재개 정책

과거 전체 백필은 우선 로컬에서 진행하고, 원격은 날짜 증분·새 공시·정정분 갱신을 담당하도록 설계한다. 초기 갱신 빈도는 시장별 장 마감 후 가격 수집과 하루 1회 재무 발견·수집을 검토한다. 실제 API 접근, 처리 시간, 데이터 신선도 요구로 주기를 정한다.

비공개 Actions를 선택하거나 실행량을 줄여야 할 경우 주 2~3회 갱신도 후보가 된다. 공급자가 과거 일봉을 제공한다면 여러 날짜를 묶어 따라잡을 수 있지만, 공시를 실제로 관측한 시각은 갱신 주기에 따라 늦어진다. 늦게 수집한 값을 이전 관측 시각으로 소급하지 않는다.

감시는 수집과 분리한다. 2시간마다 상태를 확인하더라도 매번 전종목을 다시 수집하지 않는다. 정상 진행 중이면 조용히 유지하고, 새 오류·정체·종료·필요한 사용자 조치가 있을 때 알린다.

한 공급자 계정의 토큰과 호출 예산은 공유한다. 로컬과 원격이 같은 수집 작업을 동시에 소유하지 않도록 하고, 중복 예약 실행을 막는다. 체크포인트는 시간뿐 아니라 완료한 종목·공시·페이지와 미완료 구간을 구분한다. 배치가 영속적으로 저장되기 전에 해당 구간을 완료 처리하지 않는다.

## 동기화와 PIT 보존 계약

원격과 로컬에서 같은 증권·발행사·공시를 식별할 수 있도록 기존 ID와 명시적 원천 식별자를 함께 전달한다. 원격 실행 때마다 다른 ID를 생성해 같은 대상을 새로 등록하지 않는다.

배치는 다음 정보를 포함하도록 한다.

- 배치 ID, 순서, 원천, 대상 시장과 요청 구간, 이전 체크포인트.
- 스키마·파서·매핑·검증 규칙 버전, 파일별 해시와 행 수, 부모 증거 참조.
- 기존 값·정정값과 출처, 원래 공개·수집·관측·검증 시각 및 적격성 상태.

로컬은 배치의 파일과 참조를 검증한 뒤 트랜잭션으로 적재한다. 중간에 실패하면 적재 완료 기록을 남기지 않는다. 이미 완료한 배치를 다시 받아도 가격·재무 행과 검증 결정이 중복으로 생성되지 않아야 한다.

다운로드 시각은 별도 동기화 기록으로 남긴다. 원격에서 수집한 `captured_at`, 검증된 공개 시각, 기존 `available_at`, 최초 발견·검증 시각을 다운로드 시각으로 덮어쓰지 않는다. 공개 시각이 검증되지 않은 데이터의 capture-only 제약도 유지한다.

원격에 임시 적재한 SQL 증거의 ID와 원래 시각은 보존하고, 로컬로 들어온 시각은 별도로 기록한다. 로컬에서 새로 실행한 매핑·검증·계산 결정에는 실제 로컬 실행 시각을 사용한다. 호스팅 변경만으로 과거 public PIT 적격성을 승격하지 않는다.

정정과 철회는 새 이력으로 추가한다. 가격의 원주가·수정주가 구분, 기업행동 검증, exact VWAP 입력 조건, 금융 수치의 단위·기간·연결/별도와 지표 계산 적격성은 기존 계약을 유지한다. 무료 원격 운영 자체가 clean dataset 완성을 인증하지 않는다.

Oracle의 PostgreSQL은 무료 VM에 직접 설치하는 구성이다. Oracle 관리형 PostgreSQL이 무료라는 뜻이 아니다. 전체 SQL을 원격으로 옮기는 경우에는 인덱스·로그·백업을 포함한 실제 디스크 용량을 확인한다.

## 실행비 비교 예시

아래는 월 30일, 해당 계정의 무료 사용량이 모두 남아 있다고 가정한 USD 실행비 계산이다. 실제 수집기의 실측 견적이 아니다. GitHub는 Free 비공개 저장소의 기본 Linux 2코어, Cloud Run Jobs는 미국 중부의 2 vCPU·2GiB를 가정한다. 환경별 성능과 메모리가 달라 같은 작업의 실행 시간이 달라질 수 있다.

| 총 실행 시간 | Cloud Run Jobs | GitHub 비공개 | GitHub 공개 표준 실행기 |
|---|---:|---:|---:|
| 하루 1시간으로 월 30시간 | $0 | $0 | $0 |
| 하루 2시간으로 월 60시간 | 약 $3.46 | 약 $9.60 | $0 |
| 하루 4시간으로 월 120시간 | 약 $12.06 | 약 $31.20 | $0 |

Cloud Run Jobs는 무료 CPU 240,000 vCPU초·메모리 450,000 GiB초를 차감한 뒤 CPU초당 $0.000018, GiB초당 $0.000002로 계산했다. GitHub 비공개는 월 2,000분 차감 후 분당 $0.006으로 계산했다. [Google 요금](https://cloud.google.com/run/pricing), [GitHub 요금](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

Scheduler는 같은 결제 계정의 예약 작업 3개까지 무료다. 위 표는 파일·DB·컨테이너 보관·전송·세금을 포함하지 않는다. API 응답 대기와 재시도도 실제 실행 시간에 포함한다. Google의 무료량은 미국 중부 가격 기준이므로 다른 지역은 해당 가격으로 다시 계산한다.

## 추가 구현과 검증 순서

현재 `incremental`은 명시적으로 계획된 SQL 작업 큐 재개다. 이를 장 마감 후 새 날짜 생성이나 자동 정정 스캔과 동일하게 취급하지 않는다. 현재 SQL 의존 수집기를 그대로 예약하는 것만으로 이 원격 구조가 완성되지는 않는다.

1. **실측:** 일회 증분 수집의 실행 시간·메모리·호출 수·변경분 크기를 측정하고, 후보 실행 환경의 KIS·SEC·OpenDART 접근을 확인한다.
2. **작업 생성:** 기존 전체 대상과 원래 기간을 보존하면서 날짜 증분·새 공시·필요한 정정 재검증 작업을 계획한다.
3. **재개 상태:** 원격에서 사용할 영속 작업 상태, 현재 마스터와 ID 연결, 호출 예산·중복 실행 방지 방식을 정한다. 작은 원격 DB 또는 버전이 있는 상태 파일 중 SQL 큐 의미를 보존하는 방식을 선택한다.
4. **배치 전달:** 부모 증거·해시·스키마 버전이 포함된 변경분 내보내기와 비공개 임시 저장소 저장을 구현한다.
5. **로컬 적재:** 원래 시각·ID·정정 이력을 유지하는 트랜잭션 적재, 동일 배치 재실행, 적재 확인과 백업 연결을 구현한다.
6. **무료 운영 제어:** 저장량·요청량·실행 시간의 계정 전체 사용량을 보고, 한도 근처에서 알림과 보류를 적용한다. 미수신 자료와 체크포인트는 보존한다.
7. **예약 실행:** 검증한 뒤 실행 빈도와 예산을 정해 배포한다. 별도 공개 저장소에는 필요한 수집 코드만 옮기고, 원격 적재를 확인하기 전 기존 로컬 수집의 소유권을 이전하지 않는다.

완료 판정에는 종료 직전 재개, 중복 예약, 업로드 중단, 다운로드·적재 중단, 동일 배치 재처리, 부모 참조 누락, 해시 오류, PC 장기 미접속과 정정 도착 사례를 포함한다. 예산 부족을 종목 축소나 미완료 구간의 성공 처리로 해결하지 않는다.

현재 데이터 복구·백업의 경계는 [로컬 복구 검증](recovery-runbook.md)을 따른다. 원격 전달용 임시 저장소와 독립적인 전체 백업은 별도 운영 항목으로 관리한다.
