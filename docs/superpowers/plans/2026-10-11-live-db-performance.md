# Live collection performance repair

> For agentic workers: execute the independent price-write task in the current workspace; preserve other workers' edits.

**Goal:** Reduce observed USB-disk WAL stalls and price audit heap reads while preserving data, current collectors, and fenced five-minute leases.

**Architecture:** PostgreSQL owns reloadable WAL/checkpoint settings and additive concurrent indexes. Price storage owns small SQL batches and checks the existing lease before/after each batch. The existing continuation manager alone adopts naturally finished collector generations.

**Constraints:** No collector cancellation, restart, second collector, source/checkpoint reset, relaxed expiry/fencing, database reinitialization, storage move, or durability disablement. No fsync/synchronous_commit/full_page_writes change. Current loaded Python code only changes at a natural generation transition.

**Capacity and rollback:** Fail closed unless E has at least 100GiB free before tuning and every index build (50GiB collector floor plus 50GiB reserve for soft WAL retention, indexes/temp and concurrent ingestion). Record measured space. Record each allowlisted key's existing postgresql.auto.conf override separately from its effective setting. On partial tuning failure restore existing overrides, RESET only introduced keys, reload and verify the original effective profile; preserve unrelated settings. Never automatically remove a failed index.
