# 로컬 투자 연구 플랫폼 전체 PRD

버전 0.2 검토 초안. 사용자 1명의 Windows 로컬 연구 환경을 대상으로 한다. 일봉, 한국·미국 전종목·ETF·ETN·상폐·정지, 최소 10년 이상의 목표를 [전체 기획](00-overview.md)에서 계승한다. [구현 품질·비용 계약](17-implementation-guardrails.md)의 불변식과 사용자 결정 원장을 함께 적용한다.

## 해결할 문제와 이용 흐름

무료 소스의 가격·재무 자료가 각각 다른 시점·단위·상품 범위를 갖고 있어, 단순히 합친 CSV로는 신뢰할 수 있는 전략 평가를 하기 어렵다. 데이터 수집·검증·SQL 보존·분석·화면·시그널을 같은 정의로 연결한다.

사용자는 앱을 열어 최신 수집과 누락 상태를 보고, 관심 종목의 차트·재무를 확인한다. 저장한 전략을 고정 데이터로 평가하고, 시장 레짐별 성과를 비교한 뒤 스크리닝 결과와 장 마감 후 참고 시그널을 검토한다. 실제 거래는 앱 밖에서 수동으로 판단하고, 선택적으로 체결 기록을 입력한다.

## 포함 범위

로컬 수집·자동 증분 계획·기업행동·상품·역사 universe의 공급자 적격성, 원격 수집과 로컬 동기화, 가격·재무 QC, versioned 데이터 릴리스, 백테스트·시간순 검증, 단순 레짐, 종목·전략 스크리닝, 시그널과 수동 보유 원장, 웹 UI·CSV export·운영 가이드를 포함한다.

초기에는 롱온리·시장별 자금·일봉·다음 세션 시가 가정을 사용한다. 핵심은 Python 전략을 계속 추가할 수 있는 플랫폼이고 초기 예시 네 개를 닫힌 목록·완료 조건으로 두지 않는다. 크립토·옵션·선물·tick·고빈도·자동 주문·다중 사용자·외부 공개 호스팅·Pine 호환·화면 조건 조합·AI 투자 추천은 초기 제외다. 개발용 QA 집합은 전체 데이터 대상을 대체하지 않는다.

## 릴리스 구분

| 릴리스 | 기능 | 가능한 주장 |
|---|---|---|
| R0 데이터 가시성 | 현재 수집·coverage·차트·원계정 | 보유 데이터의 상태 확인 |
| R1 연구 앱 | 연구 적격 projection·기준 백테스트·기본 레짐 | 지정 scope와 한계 안의 재현 가능한 연구 |
| R2 운용 참고 | 증분·품질 gate·스크리닝·수동 보유·시그널 | 지정 시장·종목·전략의 최신 입력에 기반한 참고 신호 |
| R3 원격 연속성 | 원격 collect/bundle/sync·무료 예산·복구 | 검증된 offline 기간 동안 변경분 전달 |
| R4 확장 준비 | Strategy/Feature/Model/Engine protocol·새 Python 플러그인 probe | 구체적 고급 방법 연결 없이 확장 계약을 확인 |

R2는 사용자 selected·데이터 품질·과거 평가/validation을 독립적으로 표시한다. 선택이 미검증 입력을 통과시키거나 편향 성과를 검증 인증으로 바꾸지 않는다. 최신 데이터가 있다고 과거 OOS/PIT 근거를 생성하지 않는다. 전체 10년 coverage 완료 선언은 별도 전수 인수를 통과해야 한다.

## 성공 지표와 목표 성능

| 항목 | 목표 | 측정 기준 |
|---|---|---|
| 데이터 신뢰 | 성공·미지원·결측·품질을 모두 표시 | 전체 target 대비 profile·기간·상품별 리포트 |
| 재현성 | 동일 run fingerprint의 핵심 산출 동일 | deterministic fixture 및 실데이터 고정 snapshot |
| 앱 첫 화면 | warm p95 2초 이내 후보 | 사용자 PC 사양 확정 후 20회 측정 |
| 단일 일봉 차트 | 3천 bars warm p95 1초 이내 후보 | 조회·전송·렌더 분리 측정 |
| 스크리닝 | 캐시 결과 열기 p95 2초 이내 후보 | 계산 시간과 화면 시간 별도 |
| 시그널 신뢰 | blocked/expired를 진입·청산으로 오표시 0건 | 인수 fixture·정정 재생 |
| 무료 운영 | 측정 범위에서 서비스 초과 과금 0 | 계정 전체 잔여량·상한 정책 |
| 수집 재개 | 누락 없이 at-least-once 전달·idempotent import | 중단·중복·순서 변경 시험 |

성능값은 약속된 실측값이 아니라 인수 후보 기준이다. RAM·디스크·대상 규모를 확인한 후 조정하고 변경 이유를 기록한다. 수익률이나 전략 수익을 제품 성공 보증으로 삼지 않는다.

## 제품 의존성과 주요 위험

무료 공급자가 상폐·과거 종목 변경·기업행동·일봉 세션·재무 공개 시각을 완전하게 제공한다는 가정은 하지 않는다. 공급자 접근 실증과 이용 조건 확인은 데이터 단계의 필수 작업이다. 확보 실패는 gap으로 남겨 비교 연구 범위를 제한한다.

백테스트 속도보다 계산·시점·비용의 일관성이 선행한다. 원격 예약 성공보다 데이터 전달·체크포인트 복구를 먼저 검증한다. 기존 100만 행 제한 릴리스 경로는 전수 스케일 실증 전 확장해야 한다.

## 인수 경로

기능별 요구는 03–08, 계약은 09–13, 실제 작업은 14, 인수 시나리오는 15에서 관리한다. 파일마다 다른 기본값을 두지 않고 공통 시각·체결·상품·예산 규칙을 해당 계약으로 연결한다.

운영 결과에 샘플·랜덤·고정 JSON을 넣어 화면을 채우거나, 다른 전략·engine·source를 요청한 결과로 표시하는 완료는 인정하지 않는다. 필수 기능의 구현 상태·데이터 준비·운영 연결·현재 결과 상태를 따로 인수한다. 정확도와 순차 공개의 선택은 DEC-01/04, 모의체결은 DEC-02, 비용은 DEC-07을 따른다.
