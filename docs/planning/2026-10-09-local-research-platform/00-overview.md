# 한국 미국 전종목 로컬 투자 연구 플랫폼 기획안

작성일 2026-10-09 KST. 버전 0.4 연결 계약 검토안. 기존 17개 정책과 전체 흐름의 추가 답변·미확정 항목을 구분하고 Invest Prototype 재발 방지 검토를 반영했다. 문서에 제시한 새 기능과 명령은 구현 예정이며, 현재 작동하는 기능은 현황 절에서 별도로 구분한다.

## 목표

한국·미국의 주식·ETF·ETN과 과거 상장폐지·거래정지 종목을 최대한 빠짐없이 로컬 SQL에 보관한다. 최소 10년 이상의 일봉·펀더멘털 이력으로 백테스트, 현재 시장 레짐 파악, 종목·전략 스크리닝, 장 마감 후 매수·매도 참고 시그널을 제공한다. 주문 전송과 자동 매매는 범위에 포함하지 않는다.

원격은 PC가 꺼져 있을 때 새 자료를 모으는 역할을 맡고, 로컬 PostgreSQL은 전체 이력과 연구 결과의 기준 저장소가 된다. 사용자는 PC를 켜고 앱을 열어 동기화 상태를 확인한 뒤 차트·분석·시그널을 이용한다. 서비스 이용료 월 0원을 우선 목표로 하며, 장비·디스크·전기 비용과 데이터 이용권은 별도로 평가한다.

## 권장 구성

**기존 PostgreSQL + Python 전략 플러그인 + 검증한 백테스트 framework adapter + FastAPI + React/TypeScript + Lightweight Charts**를 권장한다. vectorbt를 기본 엔진으로 고정하지 않고 [18 프레임워크 비교](18-framework-evaluation.md)의 Zipline-reloaded·LEAN 후보를 qualification한다. Parquet/DuckDB는 SQL에서 재생성 가능한 캐시 후보이며, 실제 데이터 의미와 품질은 앱 계약이 소유한다.

| 접근 | 장점 | 비용·제약 | 판단 |
|---|---|---|---|
| 로컬 수집과 로컬 UI | 기존 SQL 큐 재사용, 운영 단순 | PC가 꺼지면 수집 중단 | 반드시 유지할 기본·복구 경로 |
| 공개 최소 수집 코드 + 비공개 R2 전달 | 기존 설계 계승, 표준 실행기·임시 보관 무료량 활용 | 비밀값 분리, R2 초과 과금 제어·공급자 조건 | 권장 원격안, 로컬 실증 후 설정·배포 |
| 비공개 Actions 또는 Google Cloud Run | 코드 공개 없이 실행 가능 | 포함 실행량·저장·전송·계정 조건 검토 | 공개 미허용 또는 API 접근 실패 시 대안 |

현재 [원격 운영 설계](../../data/free-remote-update-local-sql.md)의 공개 최소 수집 코드 + 비공개 R2 방향을 계승한다. 사용자는 비밀값을 제외한 수집 코드 공개를 허용했다. Google 이용은 필수 조건이 아니며 Cloud Run·Drive·Apps Script를 역할별 대안으로 비교한다. 설계안 작성은 현재 저장소 공개 전환이나 클라우드 계정 설정을 뜻하지 않는다. 실제 과금 조건과 라이선스는 [출처와 결정](16-decisions-and-sources.md)에 정리했다.

PC 조회 시점의 가용 RAM은 5.3GiB, C 드라이브 여유는 39.5GiB였다. 초기 분석 worker는 1개, 동적 메모리 상한과 CPU thread 제한을 사용한다. E 드라이브 여유는 Docker의 PostgreSQL volume이 E에 있다는 증거가 아니므로 실제 volume·WSL 위치부터 확인한다. 경로 이동이나 기존 수집 프로세스 종료는 이번 문서 작성에 포함하지 않는다.

```mermaid
flowchart LR
  Providers[가격 공시 기업행동 과거 종목 소스] --> Collector[로컬 또는 원격 수집]
  Collector --> Bundle[검증된 변경분과 영속 체크포인트]
  Bundle --> Sync[로컬 동기화와 중복 방지]
  Sync --> SQL[PostgreSQL 원관측 정정 증거]
  SQL --> Release[고정 릴리스와 적격성 검사]
  Release --> Dataset[시점별 분석 데이터]
  Dataset --> Research[백테스트 레짐 스크리닝]
  Research --> Signals[장 마감 후 참고 시그널]
  Research --> API[로컬 API]
  Signals --> API
  API --> UI[웹앱 차트 결과 데이터 상태]
```

## 한 번의 요청으로 구현하는 방식

하나의 요청으로 아래 순서와 완료 조건을 실행할 수 있도록 문서를 연결한다. 구현 내부에서는 작은 작업 단위로 검증하며, 전체를 한 번에 바꾸는 방식은 사용하지 않는다.

1. **데이터 신뢰성**: 과거 universe·달력·coverage·필수 재무·기업행동·조회 성능.
2. **로컬 앱 기본 흐름**: 상태 화면, 종목 검색, 차트, 데이터 품질 표시.
3. **검증 가능한 분석**: 프레임워크 qualification, Python 전략 확장·백테스트·기본 레짐.
4. **스크리닝과 시그널**: 같은 정의를 공유하고, 수동 보유정보와 연결.
5. **원격 갱신**: 로컬에서 증분·bundle·복구를 검증한 후 예약 실행.
6. **수학 확장 준비**: 인터페이스만 확보하고 구체적 고급 방법 연결은 후속 별도 요청으로 둔다.

상폐·기업행동·PIT 데이터가 무료로 완전하지 않을 수 있다. 이 경우 UI와 명시적 부분 연구는 개발할 수 있지만, 전수 검증 완료·편향 없는 과거 성과·체결 가능성을 인증하지 않는다. 일부 적격 종목의 검증된 시그널은 전체 coverage와 구분해 제공할 수 있다. 사용자 selected 선택과 이 검증 등급은 독립이다.

01의 Q01–Q12 중 시장·주기·기간·비용 의향·자원·원격안·공개·30일 미접속·전략·clean 우선 답변은 이미 반영했다. 보유 입력·알림·성과 검증 기준 등 나머지는 문서의 기본안으로 검토할 수 있다. 구현 시에는 이미 확정한 선택을 반복 질문하지 않고 실제 계정·비용·데이터 권리와 필요한 설정만 확인한다.

추가 DEC-01–17은 17 문서의 사용자 결정 원장을 따른다. 실제 값·시각·정의·증거를 지키는 범위에서 검증·탐색 결과를 구분해 제공한다. runtime qualification과 실제 source coverage는 정책 답변과 별개로 검증하며 미실행 상태를 완료로 표시하지 않는다.

19의 Invest Prototype 검토는 기존 저장소의 통합 요청이 아니라 재발 방지 근거다. T43–T49를 추가해 보관 창·부분 실패·상태 재시작·오래된 결과 표시와 연구용 체결 가정의 경계를 인수한다. 공식 거래가능 이력 부족은 DEC-17에 따라 적격 raw OHLCV·양수 거래량 세션에서 연구용 모의체결을 허용하되 unknown 관측·한계를 보존한다.

20은 기능 간 연결의 보완이다. DEC-18의 복잡도 억제와 DEC-19의 전략별 진입 풀을 반영하고, 추가 질문 DEC-20–23은 원장 상태를 따른다. 현재 단계에서 고급 모델·범용 workflow·원격 분석·공매도·공유 계좌·실제 수량을 임의 필수로 확대하지 않는다. T50–T56은 이 연결의 재현·보유 관리·확장 경계를 인수한다.
